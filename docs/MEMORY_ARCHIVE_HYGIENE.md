# Memory archive hygiene

`plan_memory` reconciles the searchable import with the selected source snapshot.
It does not delete source memory or change native consolidated memory. Credential
skips still apply to every source; reviewing a quarantine does not authorize
importing its content.

## Ownership and retention

The existing outbox `history.json` carries an optional `archive_ownership` member:
version 1 and `roots`, a mapping from exact normalized source roots to archive
relative paths and sorted SHA-256 lists. It contains no bodies. The outbox prepare
operation saves it under the same lock and history CAS as delivery. Generated
hashes remain recognized across interruption and rollback, including a prepared
write that has not reached its destination. Existing outboxes without this member
remain valid. Multiple source roots retain their existing independent delivery
streams. Switching the active archive snapshot can replace known generated bytes;
retirement authority is limited to hashes recorded for the selected source root.

A current destination identical to clean generated bytes can acquire ownership
without changing the file. An unknown or edited destination cannot be overwritten.
Such a conflict blocks the archive publication and ingress intent. A stale owned
file retires only when its hash matches and source absence is established by a
complete traversal, or that exact source was excluded for credential findings.
An incomplete traversal never establishes deletion. Unowned or edited stale
files stay in place and appear in `archive_hygiene.preserved`; a partial result
does not claim the search directory has been cleaned.

Retirement uses the existing profile backup. Its before-image is verified, and
the original file object is moved to `quarantine-<path-digest>.bin` in that backup
using `fleet_guards.filesystem.detach_if_matches`. Both content and file identity
must match. No body enters a report, manifest, or ordinary searchable import as
part of retirement. No new history writer, journal, lock owner, quarantine service,
or storage root is introduced. These bytes need the same private retention and
access controls as existing profile before-images; they are not publishable test
data. Windows handle exclusion is required for the detach; unsupported platforms
preserve the source and fail closed.

Normal rollback retains quarantine evidence and does not republish retired files.
Other profile members retain the existing rollback CAS protection for user edits.
A restored old index may reference a retired file; replan to refresh it. Native
memory, notes and durable outbox history remain governed by their existing owners.
Cross-home restore rebinds the ownership source root only through the existing
exact scope-evidence mapping; captured hashes remain unchanged.

## Reviewed archive decisions

`plan_memory(..., reviewed_archive=rows)` takes private, explicit decisions with
exact fields:

| Field | Meaning |
| --- | --- |
| `path` | Archive-relative POSIX path; no traversal or aliases |
| `sha256` | Freshly verified destination hash, not a source hash |
| `action` | `adopt` for a selected current file/index; `quarantine` for a stale copy |
| `source_root` | Exact absolute Claude projects root |
| `review_id` | Identifier of the operator's review |

Duplicate paths, changed bytes, mismatched actions/roots, and credential-bearing
metadata reject the decision. Legacy filenames and old index markers confer no
ownership. Index text changed by this upgrade can itself require reviewed adoption
on an older installation. Keep review evidence and actual operator paths in
private settings. The planner does not write settings or persist broad approvals.

## Reviewed scopes

`plan_memory(..., reviewed_scopes=rows)` supplements the active project map. Each
row contains `project` (the exact source directory key), `scope_path` (an absolute
path), `source_root`, and `evidence_sha256`. The digest identifies the controller's
reviewed evidence; the controller must establish the historical path association.
The planner never decodes the key to guess a path and does not require an old
historical directory to remain present.
`scope_reviews` in the metadata report retains each evidence digest and its
decision status so an applied mapping can be traced back to the reviewed input.

An exact active mapping remains authoritative. An active collision remains
unmapped. Conflicting or duplicate reviewed mappings cannot settle a collision.
Unavailable active configuration is reported and does not permit a reviewed
mapping to silently replace an unknown active one. These records are not native
ingress grants, and they never rewrite Claude sources or configuration.

## Profile transaction integration

`MemoryPlan.archive_before` holds destination snapshots captured by reconciliation;
`MemoryPlan.retirements` holds hash/identity metadata. `archive.profile_changes`
converts the private plan into the existing profile change-row shape, omitting
informational native note previews. Full-profile integration must preserve those
before snapshots and attach `memory_retirement` to each retirement row.

After the existing complete-plan backup and outbox prepare, call
`archive.apply_retirement(row, codex_home, backup)` before ordinary publication.
True means the retirement has been handled; retain after-state verification.
False means ordinary publication. The hook verifies its entry in the durable
backup manifest and its before-image; it never invents backup authority. A retry
of a completed hook requires the retained file's exact original identity and bytes.

Before ordinary rollback restoration, call `archive.preserve_on_rollback(row)`.
True requires retaining the evidence and reporting `quarantined_memory_evidence`.
Install both hooks before declaring `MEMORY_ARCHIVE_HYGIENE_VERSION = 1` on
`profile_sync`. Standalone `apply_memory_plan` uses the profile transaction and
refuses a retirement when this integration capability is absent. The full profile
builder must not discard retirement metadata or feed an unannotated retirement
to the generic delete branch.

## Approved native notes

Use the existing [authorization and outbox API](MEMORY_OUTBOX.md). Review project
scope and archive conflicts, then preview with a fresh approved `request_id`, the
exact project-key `scope`, and `periodic=False`. Apply the original private plan.
The existing outbox publisher writes an approved note after archive publication.
`periodic=True` or `memory_outbox.authorize` is appropriate only for an approved
recurring scope. An ingress instructions file is availability, not authorization.
No API here edits native `MEMORY.md` or summaries; note publication does not prove
consolidation or recall. Credential exclusions are never bypassed.
